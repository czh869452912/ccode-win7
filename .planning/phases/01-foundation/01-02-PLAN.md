## Affected Files and Patterns

The 25 bare `except Exception:` blocks are distributed across 16 files. Each occurs in a specific context that determines the appropriate replacement:

### File I/O + JSON parsing (most common)
Files: permissions.py, harness/task_store.py, session_store.py, project_memory.py, tool_commit.py, core/adapter.py, frontend/gui/backend/server.py, frontend/gui/launcher.py, frontend/tui/services/*.py, workspace_recipes.py

Typical pattern:
```python
try:
    with open(path, "r", encoding="utf-8") as handle:
        data = json.load(handle)
except Exception:
    return default_value
```

Replacement: `except (OSError, json.JSONDecodeError, ValueError):`
- `OSError` covers FileNotFoundError, PermissionError, IsADirectoryError, etc.
- `json.JSONDecodeError` covers malformed JSON
- `ValueError` covers edge cases in data processing

### Text content reading
File: tools/discovery_ops.py

Pattern:
```python
try:
    content, _, _ = ctx.read_text(absolute_path)
except Exception:
    continue
```

Replacement depends on what `ctx.read_text()` raises — typically `(OSError, UnicodeDecodeError, ValueError)`

### Event/state handling
Files: inprocess_adapter.py

Pattern:
```python
try:
    self._emit_event(...)
except Exception:
    pass
```

Replacement: `except (RuntimeError, ValueError, TypeError):` or similar based on what the event emission can raise.

### UI service operations
Files: frontend/tui/services/workspace.py, sessions.py, timeline.py, artifacts.py

Pattern:
```python
try:
    result = some_service_call()
except Exception:
    return default
```

Replacement varies by service call type.

## Strategy

1. **Batch 1**: File I/O + JSON files (permissions.py, task_store.py, session_store.py, project_memory.py, tool_commit.py, core/adapter.py, workspace_recipes.py)

3. **Batch 3**: Special cases (discovery_ops.py, inprocess_adapter.py)

For each bare except:
1. Read the surrounding code to understand what operations occur in the try block
2. Determine which specific exceptions those operations can raise
3. Replace `except Exception:` with `except (SpecificException1, SpecificException2, ...):`
4. Add fallback logging for unexpected exceptions (see Task 2 guidance)
5. If the except block returns a default value, preserve that behavior
6. If the except block logs or silently passes, preserve that behavior
