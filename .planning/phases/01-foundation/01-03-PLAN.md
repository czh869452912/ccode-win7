**If deprecation warnings from third-party libraries remain:**

**If `ResourceWarning` or other warnings appear:**
- ResourceWarning (unclosed files/sockets): Fix by ensuring proper context managers (`with` statements) or explicit close() calls
- PendingDeprecationWarning: Treat same as DeprecationWarning
- RuntimeWarning: Investigate root cause

**Progressive warning configuration (addresses review concern about overly strict config):**

Step A — Start with warning (not error) to see what's left:
```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
filterwarnings = [
    "default::DeprecationWarning:embedagent.*",  # Warn for project code
    "ignore::DeprecationWarning",                  # Ignore third-party for now
]
```

Step B — Once project code is clean, upgrade to error for project code only:
```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
filterwarnings = [
    "error::DeprecationWarning:embedagent.*",     # Error for project code
    "ignore::DeprecationWarning:third_party.*",   # Ignore known third-party
]
```

**Important:** Only suppress warnings from external code, never from project code. Document all suppressions with comments explaining why.

**Verification approach:**

```bash
# Step B: Check with error config (project code only)

# Should pass if project code is clean
```
